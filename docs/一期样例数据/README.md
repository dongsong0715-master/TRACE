# TRACE一期样例数据

这些内容由模型起草并通过本地脚本确定性整理，供一期开发与功能验证使用。没有真实企业招聘信息或真实学生记录，也没有伪造真实API调用日志。数据版本为`demo-v1`，规则版本为`rules-v1`。

| 文件 | 内容 |
| --- | --- |
| jobs.json | 30条岗位，Python开发、Web前端、数据分析各10条 |
| interview_questions.json | 30题，每类难度1/2/3的数量为4/4/2 |
| diagnosis_template.json | 10题固定问卷及输入范围 |
| rules.json | 分类技能、四维画像、推荐权重、评分与调用限制 |
| demo_profiles.json | 6组资料与答案，不包含密码或预先写死的推荐结果 |
| validation_cases.json | 14个起始验证案例，包括公式、非法响应与权限约束 |
| generation_manifest.json | 数据数量和六个数据文件的SHA256 |
| 模型生成与调用提示词.md | 扩充数据和真实API调用的提示词模板 |

开始开发时，先解析JSON并执行类型、范围和引用校验，再实现导入命令。`jobs.json`和`interview_questions.json`的根结构是数组；其他文件是带版本的对象，`demo_profiles.json`也是数组。数据库ID由导入程序分配，文件中的`code`是稳定业务编码，不能直接当数据库自增ID使用。

导入映射：岗位`required_skills`写入`jobs.required_skills_json`，题目`rubric`写入`interview_questions.rubric_json`；岗位和题目的`content_hash`由程序对规范化内容计算。不要把生成时间、数据库ID计入内容哈希。同code、同版本、同内容跳过；同版本不同内容拒绝并要求升版。首次岗位`jd_version=1`，正文更新递增并重新构建索引。

`demo_profiles`的`answers`用于诊断接口；初始化脚本另建相应测试账号，将Q01、Q02、Q03映射至基础资料。账号密码本地临时生成并哈希保存，不提交到仓库。开发页面应显示演示标识。

岗位公司、薪资和描述均为合成内容。`source_url=null`，页面不提供虚构的真实投递链接。向量必须由本地真实BGE模型生成；真实解释和面试评分必须由实际API调用产生。当前数据文件不包含可用于代替这些步骤的预生成向量或成功日志。

`rules.json`中的公式字符串是规则说明，由开发者实现确定性函数，不使用`eval`执行。题库参考答案用于提示与检查，不要求学生逐字匹配关键词。Q04必须按所选类别回答5项技能，0是明确不会，缺失是尚未回答。

验证案例中的`mock_response`只用于测试错误处理；`kind`用于选择测试函数。C01、C02验证画像公式，C05验证排序加权公式而非BGE效果，C07、C08验证面试加权与均分。其余案例需在应用接口实现后执行，不能把文件存在视作测试通过。

正式评估时另建未用于调整规则的查询集，人工核对岗位相关性和评分合理性。扩充数据时保存新版本，更新manifest并保留旧测试，不在应用启动或每次请求时随机重生成整个题库。

配套文档为上级目录的`TRACE需求分析与开发文档.md`和`TRACE数据库结构.sql`。当前目录不是可直接运行的完整应用。

附带`validate_samples.py`只使用Python标准库。运行`python validate_samples.py`可核对JSON结构、枚举、数量、哈希和数值算例；它不会连接数据库、生成BGE向量或调用付费API。应用测试仍需按开发文档执行。
