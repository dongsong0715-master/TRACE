# TRACE 团队开发接力说明

日期：2026-10-06　起步版本：0.1.0

本次交付完成账号基础与前后端连接，不等同于一期所有业务完成。完整12表仍以开发文档为业务设计基线；当前迁移只落地账号和学生资料。

## 可以直接复用的基础

后端 `app/api/dependencies.py` 提供 DB、CurrentUser、StudentUser 和 require_admin；`core/errors.py` 提供业务异常与统一响应；`services/accounts.py` 展示一次事务、归属限定和乐观版本更新。
前端 `api/client.ts` 统一 Cookie 请求与错误，`stores/auth.ts` 处理会话恢复，路由守卫控制学生页面；共享 header 和 field 控件支持不同模块统一风格。

## 建议认领边界

| 工作包 | 主要目录 | 首个可验收提交 | 依赖 |
| --- | --- | --- | --- |
| 职业诊断 | algorithms/diagnosis、api/modules、views/diagnosis | 10题草稿保存、四维计算、规则版本 | 当前账号与资料 |
| 岗位与个人记录 | models、services、views/jobs/favorites/applications | 岗位导入/详情、收藏幂等、本人手动投递状态 | 当前账号；固化 jobs.json |
| RAG与真实模型 | algorithms/retrieval、ai/provider/prompts/validation | 真实 BGE 切块索引、检索证据、真实 API 解释 | 岗位表、诊断画像 |
| 面试与报告 | api/modules、services、ai/validation、views/interviews | 固定5题保存恢复、整场评分和失败处理 | 题库导入、真实模型适配 |
| 公共内容维护与集成 | scripts、api/modules、views/admin | 岗位/题库维护、索引构建命令、一期串联 | 对应业务表与接口 |

目录表是协作边界，不是必须由五个人分别负责。项目组按人数分配，避免两人同时改同一个基础文件。

## 推荐开发顺序

1. 所有人拉取起步仓库，独立生成配置并跑通注册、登录、编辑资料与退出。
2. 并行实现诊断与岗位/题库导入。新增迁移时沟通 revision，保持单一 head。
3. RAG成员读取真实岗位与画像，建立 BGE 索引；先验证检索，再接真实解释 API。
4. 面试成员复用模型适配和响应验证；收藏、投递成员复用岗位对象与账号依赖。
5. 合并公共维护与学生完整流程，按开发文档进行一期验收并保存真实调用证据。

ARIMA、分级帮扶和辅导员闭环二期再安排，一期不要为它们建立空路由、菜单或表。

## 启动数据

模型生成数据已从文档样例目录按字节复制到 `data/demo/v1` 和 `data/rules/v1`。
30条岗位、30道面试题、10题问卷、6组虚构画像、14组验证样例和演示规则均有固定版本。它们还未由当前起步代码导入业务表。
后续 seed_data 命令按 code 与哈希实现幂等导入；真实 BGE 向量由程序生成，不能用模型编造的随机向量替代。

当前 `frontend/src/dev/fixtures.ts` 仅供风格原型：三条岗位与两段示例解释不属于真实 RAG 输出，也不会导入数据库。

## 视觉基调

采用用户最新确认的 Product Design 第1张：白色顶部导航、蓝色主操作和选中状态、灰色画像侧栏。岗位探索为“个人画像—候选列表—详情与证据”的三栏工作区，窄屏转换为上下阅读。登录、注册、工作台和资料页统一使用蓝白令牌。
设计截图与对照资料按项目负责人要求仅保留在本机，不上传仓库。团队以 `frontend/src/styles/tokens.css`、共享 AppHeader/AuthLayout 及可运行的 `/design-preview` 页面为视觉依据。
岗位详情图片 `frontend/public/images/career-desk.png` 根据参考图单独生成，属于页面实际使用的演示视觉素材；不代表真实岗位的企业办公环境。图标使用已有 Phosphor 库，实际功能验证摘要见 `docs/起步验证记录.md`。
登录/注册左侧采用生成素材 `frontend/public/images/employment-background.png`，配合校园到职场标签；完整生成提示词保存于 `docs/design/employment-background-prompt.md`。正式访客导航不再提供“风格预览”入口，开发者仍可通过直接URL访问原型。
登录后的AppHeader统一为玻璃吸顶导航：菜单随页面滚动保持top:0，采用半透明白色、背景模糊与浅阴影；后续业务页复用该组件即可。新增弹层注意层级，避免遮挡导航或被导航覆盖。
登录、注册、工作台和资料页是相同视觉语言下的新页面；源图本身是岗位探索，因此不要求登录页复制岗位列表。

技术路线按项目文档保留 Vue，未使用 Product Design 的 React 独立原型模板。Element Plus 已锁定依赖，当前简单表单用原生可访问控件；复杂控件需要时按需引入并换肤。当前不引入 ECharts，待真实画像图表实现时再安装。
