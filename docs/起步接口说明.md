# 起步接口说明

认证 Cookie 为 trace_session，HttpOnly、SameSite=Lax、Path=/api，默认2小时。所有写请求必须带精确的 PUBLIC_ORIGIN；学生注册拒绝 role/user_id 等额外字段。Cookie 无自动续期，退出撤销本账号的全部现有会话。

## 注册与登录

```json
POST /api/v1/auth/register
{"username":"student_01","password":"由用户输入的独立密码","nickname":"小苏"}
```

用户名限3–64位 ASCII 字母、数字、下划线，统一小写；昵称去掉首尾空白，限1–64字；密码限8–128字符。注册创建学生账号与本人资料，返回201，但不自动登录。

```json
POST /api/v1/auth/login
{"username":"student_01","password":"由用户输入的独立密码"}
```

成功设置 Cookie，并返回本人账号与资料。错误的用户名、密码或停用账号均返回401 INVALID_CREDENTIALS，不区分账号是否存在。

## 本人资料

GET /api/v1/me 返回账号，ID字符串、role、is_demo和profile。profile含 nickname、education、target_category、preferred_cities、version；管理员可为null。

```json
PATCH /api/v1/me/profile
{"version":1,"nickname":"小苏","education":"bachelor","target_category":"python","preferred_cities":["北京","天津"]}
```

支持部分字段更新，但必须带 version 且至少一个资料字段。education 可为 null、college、bachelor、master；target_category 可为 null、python、frontend、data。城市列表最多5项，每项1–64字，去首尾空格且不得重复；清空使用[]。昵称和城市字段不接受null。成功后version递增，旧版本返回409 PROFILE_VERSION_CONFLICT。

学生无需也不得传入 user_id，服务端根据当前会话限定资料归属。管理员修改学生资料返回403。

## 响应与错误

```json
{"data":{"id":"1","username":"student_01","role":"student","is_demo":true,"profile":{}},"request_id":"uuid"}
```

```json
{"error":{"code":"UNAUTHENTICATED","message":"请先登录"},"request_id":"uuid"}
```

| 状态 | 当前错误码 | 前端处理 |
| --- | --- | --- |
| 401 | UNAUTHENTICATED / INVALID_CREDENTIALS | 受保护页面回到登录；登录表单显示错误 |
| 403 | ORIGIN_REJECTED / FORBIDDEN | 检查配置或权限，不自动重试写操作 |
| 409 | USERNAME_EXISTS / PROFILE_VERSION_CONFLICT | 换用户名，或用户主动载入最新资料 |
| 422 | VALIDATION_ERROR / EMPTY_UPDATE | 修正输入，不回显原始密码 |
| 503 | DATABASE_UNAVAILABLE | 显示服务不可用；恢复会话时不把网络故障当成退出 |

request_id 同时在响应头 X-Request-ID 返回；个人响应 no-store。配置错误使应用启动失败，不使用硬编码 JWT 密钥兜底。

## 后续统一约定

新增改密或账号停用行为时，必须同事务递增 token_version。个人资源除检查登录，还要检查资源 user_id；前端隐藏按钮不能代替服务端鉴权。
后续限额与真实模型错误沿用文档中的429、503、幂等键与调用状态设计。当前起步仅提供账号基础，没有实现调用预算或 AI 成本账本。
